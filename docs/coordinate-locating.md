# 坐标定位方法论

## 核心原则

**永远不要通过截图像素位置反推基准坐标。** 截图经过缩放，像素位置与触摸坐标之间存在不可控的误差（实测偏差可达 20~30 像素）。

## 正确的定位方法（按优先级）

### 方法1: getevent 抓取（最可靠）

```bash
python3 tools/locate_tap.py --count 3
```

让用户在真机上点击目标按钮，工具自动输出基准坐标。**这是唯一 100% 可靠的方法。**

适用于：
- 纯图标按钮（无文字标签）
- OCR 坐标不准的情况
- 任何需要精确定位的场景

### 方法2: OCR 文字定位 + y 偏移修正

OCR 返回的是文字区域中心，但按钮的实际点击热区通常在文字**下方约 20px**。

```
实际点击 y = OCR文字 y + 22  (经验值)
```

适用于：
- 菜单中有文字标签的按钮
- 文字按钮间距大、不容易误触

**注意：** 菜单≡打开后第一页的按钮（公会、活动等）OCR 坐标直接可用（y 偏移较小），因为它们的文字在图标下方、按钮整体较大。

### 方法3: 颜色/轮廓检测

用图像处理在截图中定位特定颜色区域（如橙色选中标签），计算中心位置。

适用于：
- 需要判断哪个标签被选中
- 按钮有明显颜色特征

## 设备参数（ZY22LJC9ST）

| 参数 | 值 |
|------|------|
| 屏幕分辨率 | 2712 x 1220（横屏）|
| 基准分辨率 | 1280 x 575 |
| 缩放比 | scale_x=2.119, scale_y=2.122 |
| 触摸面板 | /dev/input/event10 |
| 触摸范围 X | 0 ~ 19520 |
| 触摸范围 Y | 0 ~ 43392 |

## 坐标映射公式

### 触摸原始 → 设备屏幕坐标（横屏）
```
screen_x = touch_y * 2712 / 43392
screen_y = (19520 - touch_x) * 1220 / 19520
```

### 设备屏幕 → 基准坐标
```
base_x = screen_x / 2.119
base_y = screen_y / 2.122
```

### 基准坐标 → 设备屏幕（ScaledADB.tap 使用）
```
device_x = base_x * 2.119
device_y = base_y * 2.122
```

## 常见失败原因

1. **OCR y 坐标偏高 20px** — 文字区域 ≠ 按钮点击区域
2. **屏幕边缘触摸拦截** — y>540 的点击可能被系统手势区域拦截
3. **面板遮挡** — 弹窗/面板的透明区域可能拦截触摸事件
4. **菜单滚动状态不确定** — 菜单需要滚动才能看到的按钮位置不固定

## 定位流程 SOP

1. **有文字标签的大按钮**: 直接用 OCR 坐标 + y偏移
2. **纯图标/小按钮/标签页**: 
   - 运行 `python3 tools/locate_tap.py`
   - 让用户在真机上点击
   - 记录输出的基准坐标
   - 用 `--verify X Y` 验证
3. **不确定时**: 永远选择 getevent 方式，不要猜
